# مساحة مراحل تطوير RAVEN23 Backend

> المستودع: `m5ham3ds/RAVEN23-BACKEND`  
> الفرع الأساسي: `main`  
> Commit خط الأساس الذي تمت مراجعته: `9f29fa55afa21c0445be82d4590a4a532bb1747c` — 21 نوفمبر 2026  
> حالة هذه الوثائق: **إعداد الخطة فقط — لم يبدأ تنفيذ مراحل التطوير بعد.**

هذا المجلد هو المرجع الرسمي الوحيد لخطة تطوير Backend، والأدوات، وقرارات التصميم، وقواعد المستخدم، وحالة كل مرحلة، وأدلة اكتمالها.

## ابدأ بالقراءة بهذا الترتيب

1. [MASTER_PLAN.md](MASTER_PLAN.md) — الخطة الشاملة وتقسيم المراحل واعتمادياتها.
2. [BASELINE_AUDIT.md](BASELINE_AUDIT.md) — نتائج مراجعة المستودع الحالية وما لم يتم التحقق منه بعد.
3. [TOOLS_AND_SERVICES.md](TOOLS_AND_SERVICES.md) — الأدوات والتقنيات والخدمات الحالية والمقترحة.
4. [USER_RULES_AND_CONSTRAINTS.md](USER_RULES_AND_CONSTRAINTS.md) — قواعد المستخدم وقيوده غير القابلة للتجاوز.
5. [EXECUTION_PROTOCOL.md](EXECUTION_PROTOCOL.md) — آلية العمل والاختبار وتسجيل النتائج وإغلاق المرحلة.
6. [STATUS.md](STATUS.md) — الحالة الحالية لكل مرحلة وما يمنع البدء أو الإغلاق.
7. [DECISIONS.md](DECISIONS.md) — سجل القرارات المعمارية والمنتج.
8. ملفات `PHASE-XX-*.md` — مواصفات كل مرحلة ومعايير قبولها.
9. [reports/PHASE_REPORT_TEMPLATE.md](reports/PHASE_REPORT_TEMPLATE.md) — القالب الإلزامي لتقرير كل مرحلة.

## قاعدة هذا المجلد

- مواصفة المرحلة تُكتب قبل تنفيذها.
- عند إيقاف مرحلة أو حظرها أو إكمالها، ينشأ تقرير مستقل جديد داخل `reports/`.
- لا يُنشأ تقرير نجاح وهمي قبل تنفيذ العمل.
- لا تُحذف التقارير السابقة ولا تُستبدل؛ التصحيحات تكون في تقرير إضافي مع توضيح السبب.
- المرحلة لا تُعتبر مكتملة بمجرد نجاح البناء؛ يجب أن تتحقق معايير القبول مع أدلة مرتبطة بالـ commit الصحيح.
- إذا كانت المرحلة مكتملة برمجيًا لكنها تنتظر حسابًا أو سرًا أو موافقة أو جهازًا حقيقيًا، يُسجل الجزء المنجز والجزء المنتظر بوضوح، ولا توصف المرحلة كلها بأنها مكتملة.
- بعد كل تغيير حالة، يجب تحديث `STATUS.md` و`MASTER_PLAN.md`.

## سلامة هذا التغيير

هذه الوثائق فقط. لا يتغير كود التطبيق أو إعدادات Render/Neon أو بيانات المستخدمين أو حسابات الإنتاج، ولا يتم إنشاء أي موارد AWS في هذا التغيير.
